# Usanidi wa Mwongozo uliopanuliwa

Hati hii inaorodhesha hatua za **kupeleka BTCPay Server kwa mwongozo** na vipengele vya ziada vinavyohusiana. Kufuata hatua hizi kunaweza kuchukua muda mrefu. Njia fupi na ya kivitendo zaidi ni kutumia [usambazaji wa msingi wa docker](https://github.com/btcpayserver/btcpayserver-docker).

Maelekezo pia yanajenga vipengele vyote vya programu kutoka kwenye chanzo ambayo inaweza kuwa faida kwa hali fulani za ukaguzi na/au usalama.

:::danger

#### Haipendekezwi kwa matumizi ya uzalishaji

Usakinishaji wa mwongozo HAUPENDEKEZWI kwa matumizi ya uzalishaji isipokuwa una uhakika sana na Mfumo wako wa Uendeshaji na utaalamu wa usalama wa Bitcoin. Ikiwa huna uhakika, tumia usambazaji wa docker au mojawapo ya [chaguzi nyingine za usambazaji](./README.md).

#### Lazima uwe na ujuzi wa kiufundi na uweze kutatua masuala yoyote mwenyewe. Jamii haitatoa msaada mkubwa kwa usambazaji huu.

:::

## Muhtasari wa Hatua za Usakinishaji

Maelekezo katika makala haya yamejaribiwa kwenye Ubuntu 20.04. Yanapaswa kutumika kwa usambazaji mwingine wa msingi wa Linux. Pia yanategemea vipengele vyote kuwa kwenye mwenyeji au mashine pepe sawa. Inawezekana kugawanya vipengele katika wenyeji tofauti lakini maelekezo haya hayaelezi hilo.

Jina la mwenyeji la mfano la `mainnet.demo.btcpayserver.org` limetumika, linahitaji kubadilishwa na jina la mwenyeji unalotumia kwa BTCPay Server yako.

### Usalama

Ikiwa unatumia maelekezo haya kusakinisha BTCPay Server iliyounganishwa kwenye Bitcoin mainnet basi kwa uchache unapaswa kuelewa jinsi mifumo ya pochi inavyofanya kazi. Inapendekezwa sana kusoma makala mawili hapa chini na kuuliza maswali ikiwa chochote hakiko wazi.

- [BTCPay Wallet FAQ](/FAQ/Wallet.md)
- [Lightning Network and BTCPay (sehemu ya kwanza)](/LightningNetwork.md)

Kama msaada wa ziada, hapa chini ni orodha ya sheria za iptables na maelekezo ambayo yanapaswa kujumuisha bandari zote zinazohitaji kufunguliwa. **HAKUNA DHAMANA**. Tumia kwa hatari yako mwenyewe, **ikiwa ni pamoja na hatari ya kujifungia nje**.

Katika hatua hii ikiwa bado umeunganishwa kwenye kikao chako cha ssh ni ishara nzuri. Ikiwa sivyo, sheria ni za muda na unaweza kutumia njia yoyote uliyonayo kuwasha upya seva yako kwa mbali na ujaribu tena.

Sheria sasa zimetumika kwa muda. Ili kutumia sheria kiotomatiki kila wakati seva yako inapoanza tumia kifurushi cha `iptables-persistent`.

```bash
~$ sudo apt install iptables-persistent
```

Ikiwa baadaye utabadilisha sheria za iptables na unataka kuzihifadhi katika kuwasha upya, tumia amri hapa chini.

```bash
~$ sudo netfilter-persistent save
```

## NGINX na Let's Encrypt

**NGINX** inatumika kama seva ya wavuti kusimamia maombi ya HTTP kwa BTCPay Server na Ride The Lightning. Ikiunganishwa na **Let's Encrypt** inaruhusu upatikanaji na upya bila mshono wa cheti cha TLS kwa mfano wako wa BTCPay Server.

Let's Encrypt ni huduma ya bure ya kupata na kusasisha vyeti vya TLS. Huduma hii inakuja na hati zinazoweza kusakinishwa ili kusimamia kiotomatiki mchakato mzima.

##### Sakinisha

##### 1. Sakinisha NGINX.

```bash
~$ sudo apt install nginx
```

##### 2. Sakinisha Let's Encrypt

```bash
~$ sudo apt install certbot python3-certbot-nginx
```

##### Usanidi

##### 1. Cheti cha TLS cha Let's Encrypt

Lazima uunde rekodi ya A au AAAA kwa **\<jina lako la kikoa\>** inayoelekeza kwenye anwani ya IP ya mfano wako wa seva.
Ikiwa seva yako iko nyuma ya NAT basi unahitaji kuelekeza bandari 80 kwenye mfano wako.

Hati ya **certbot** inafanya kazi kwa kuangalia faili maalum kwenye seva ya wavuti inayopangisha kikoa kilichoombwa. Ikiwa haiwezi kupata faili, cheti cha TLS hakitotolewa. Ikiwa jaribio la awali linashindwa, litajaribiwa mara kwa mara au unaweza kuendesha tena amri hiyo.

```bash
sudo certbot --nginx -d <jina lako la kikoa> # (mfano: sudo certbot --nginx -d mainnet.demo.btcpayserver.org)
```

##### 2. Ongeza faili ya usanidi wa NGINX

Faili ya usanidi hapa chini imenakiliwa kutoka kwenye usakinishaji wa docker wa BTCPay Server.

Tafuta "mainnet.demo.btcpayserver.org" na ubadilishe na jina lako la kikoa.

```bash

```

```
        ssl_prefer_server_ciphers on;

        ssl_certificate_key /etc/letsencrypt/live/mainnet.demo.btcpayserver.org/privkey.pem;
```

##### 3. Unda faili ya usanidi

Mfano wa **faili ya usanidi** inapatikana kwenye hifadhi ya Bitcoin Core kwenye https://github.com/bitcoin/bitcoin/blob/master/share/examples/bitcoin.conf.

Unda **faili ya bitcoin.conf** inayofaa mahitaji yako. Faili ya mfano inayofaa kwa BTCPay Server imeonyeshwa hapa chini. Usanidi huu haupogoi blocks ambayo inamaanisha kufikia Mei 2019 utahitaji GB 235 kwa blockchain ya Bitcoin.

```bash
~$ vi bitcoin.conf
```

```
server=1                              # inahitaji RPC kwa btcpay.
rpcbind=127.0.0.1                     # loopback ni msingi kwa 0.18.0 lakini hakuna shida kuhakikisha.
whitelist=127.0.0.1                   # kwa nbxplorer.
rpcallowip=127.0.0.1/32               # loopback ni msingi lakini tena hakuna shida.
zmqpubrawblock=tcp://127.0.0.1:28332  # inahitajika kwa lightning.
zmqpubrawtx=tcp://127.0.0.1:28333     # inahitajika kwa lightning.
#prune=5000                           # Inapendekezwa ikiwa hakuna nafasi ya kutosha ya diski kwa blockchain kamili ya GB 600+.
```

Nakili faili kwenye saraka iliyobainishwa katika faili ya huduma ya systemd na toa ruhusa za kusoma kwa watumiaji wote.

```bash
~$ sudo mkdir -p /etc/bitcoin
~$ sudo cp bitcoin.conf /etc/bitcoin
~$ sudo chmod 644 /etc/bitcoin/bitcoin.conf
```

##### 5. Unda huduma ya systemd

Mfano wa **faili ya huduma ya systemd** inapatikana katika hifadhi ya Bitcoin Core kwenye https://raw.githubusercontent.com/bitcoin/bitcoin/master/contrib/init/bitcoind.service.

Hariri faili ya huduma kulingana na mahitaji yako.

Katika mfano hapa chini **Mtumiaji** na **Kikundi** vimebadilishwa kutumia mtumiaji wa `admin` badala ya kuhitaji mtumiaji mpya wa `bitcoin`. Ikiwa mtumiaji wa `admin` kwenye mfumo wako amekusudiwa kuendesha `BTCPayServer` hii ni chaguo la busara. Vinginevyo, fikiria kuunda mtumiaji maalum wa `bitcoin`.

```bash
~$ vi bitcoind.service
```

```
[Unit]
Description=Bitcoin daemon
After=network.target

[Service]
ExecStart=/usr/bin/bitcoind -daemon \
                            -pid=/run/bitcoind/bitcoind.pid \
                            -conf=/etc/bitcoin/bitcoin.conf \
                            -datadir=/var/lib/bitcoind

# Make sure the config directory is readable by the service user
PermissionsStartOnly=true
ExecStartPre=/bin/chgrp admin /etc/bitcoin

# Process management
####################

Type=forking
PIDFile=/run/bitcoind/bitcoind.pid
Restart=on-failure
TimeoutStopSec=600

# Run as admin:admin
User=admin
Group=admin

# /run/bitcoind
RuntimeDirectory=bitcoind
RuntimeDirectoryMode=0710

# /etc/bitcoin
ConfigurationDirectory=bitcoin
ConfigurationDirectoryMode=0710

# /var/lib/bitcoind
StateDirectory=bitcoind
StateDirectoryMode=0710

# Hardening measures
####################
# Provide a private /tmp and /var/tmp.
PrivateTmp=true

# Deny access to /home, /root and /run/user
ProtectHome=true

# Mount /usr, /boot/ and /etc read-only for the process.
ProtectSystem=full

# Disallow the process and all of its children to gain
# new privileges through execve().
NoNewPrivileges=true

# Use a new /dev namespace only populated with API pseudo devices
# such as /dev/null, /dev/zero and /dev/random.
PrivateDevices=true

# Deny the creation of writable and executable memory mappings.
MemoryDenyWriteExecute=true

[Install]
WantedBy=multi-user.target
```

Mara tu faili ya huduma iko tayari, kamilisha amri hapa chini.

```bash
~$ sudo cp bitcoind.service /etc/systemd/system
~$ sudo systemctl enable --now bitcoind
~$ sudo systemctl status bitcoind
...
Jul 26 21:51:52 ubuntu systemd[1]: Started Bitcoin daemon.
```

Ikiwa jaribio la kuanza linaonyesha ujumbe wa hitilafu, angalia kumbukumbu kwa kutumia:

```bash
sudo journalctl -xe --unit bitcoind
```

##### 6. Unda kiungo cha ishara kwenye faili ya kuki ya bitcoind

Mteja wa `bitcoin-cli` anahitaji kuthibitisha kwa `bitcoind` kwa simu za RPC. Njia rahisi ya kuruhusu hili ni kuunda kiungo cha ishara kwenye faili ya kuki.

```bash
~$ cd ~
~$ ln -s /var/lib/bitcoind/.cookie .bitcoin/.cookie
```

Sio muhimu kufanya hatua hii lakini ikiwa haijafanywa basi kila amri ya `bitcoin-cli` inahitaji kubainisha njia ya faili ya kuki kama ilivyo hapa chini.

```bash
~$ bitcoin-cli -rpccookiefile=/var/lib/bitcoind/.cookie getblockchaininfo
```

```bash
~$ sudo systemctl start lnd
```

Baada ya daemon kuanzishwa upya, pochi inahitaji kufunguliwa:

```bash
~$ lncli unlock
```

Ikiwa `Ride The Lightning (RTL)` imesakinishwa, angalia sehemu inayofuata, inaweza kuwa imesimama wakati lnd ilipotea kwa hivyo itahitaji pia kuanzishwa upya.

```bash
~$ sudo systemctl start rtl
```

## Ride The Lightning (RTL)

**Ride the Lightning** ni programu ya Node.js ya kusimamia wenza wako wa Lightning, njia, pochi n.k.

Faida ya kazi iliyofanywa katika BTCPay Server ni kwamba ukurasa wa wavuti wa RTL unaweza kudhibitiwa na kufikiwa kwa njia sawa na tovuti ya BTCPay.

##### Sakinisha

##### 1. Sakinisha vitegemezi

```bash
~$ sudo apt install nodejs build-essential npm
```

##### 2. Jenga RTL

```bash
~$ cd ~/src
~$ git clone https://github.com/Ride-The-Lightning/RTL.git
~$ cd RTL
~$ npm install --only=prod
```

##### 3. Unda faili ya usanidi

Nakili faili ya sampuli ya usanidi kutoka `sample-RTL-Config.json` na urekebishe ipasavyo. Mfano unaofanya kazi na maelekezo yote katika hati hii umeonyeshwa hapa chini.

```bash
~$ cp src/RTL/sample-RTL-Config.json RTL-Config.json
~$ vi RTL-Config.json
```

```json
{
  "port": "3000",
  "defaultNodeIndex": 1,
  "SSO": {
    "rtlSSO": 1,
    "rtlCookiePath": "/var/lib/rtl/.cookie",  # Inahitaji kufanana na thamani katika mipangilio ya systemd ya BTCPay.
    "logoutRedirectLink": "https://mainnet.demo.btcpayserver.org/login"
  },
  "nodes": [
    {
      "index": 1,
      "lnNode": "Node 1",
      "lnImplementation": "LND",
      "Authentication": {
        "macaroonPath": "/var/lib/lnd/data/chain/bitcoin/mainnet",
        "configPath": "/etc/lnd/lnd.conf"
      },
      "Settings": {
        "userPersona": "MERCHANT",
        "themeMode": "DAY",
        "themeColor": "PURPLE",
        "channelBackupPath": "/home/admin/rtl/backup/node-1",
        "enableLogging": false,
        "lnServerUrl": "https://localhost:8080/v1",
        "swapServerUrl": "http://localhost:8081/v1",
        "fiatConversion": false
      }
    }
  ]
}
```

Kumbuka kuwa RTL ina tabia na mahitaji tofauti ikilinganishwa na huduma zingine zilizoelezwa katika maelekezo haya, hasa:

1. Faili ya usanidi inahitaji kuwepo katika saraka ya data ya RTL,
2. Mchakato wa RTL unaweza kuandika sasisho kwenye faili ya usanidi.

```bash
~$ sudo mkdir -p /var/lib/rtl
~$ sudo cp ~/RTL-Config.json /var/lib/rtl
~$ sudo chown admin:admin -R /var/lib/rtl
~$ sudo chmod 644 /var/lib/rtl/RTL-Config.json
```

##### 4. Unda huduma ya systemd

```bash
~$ vi rtl.service
```

```
[Unit]
Description=Ride The Lightning
Requires=lnd.service
After=lnd.service

[Service]
Environment="RTL_CONFIG_PATH=/var/lib/rtl"
WorkingDirectory=/var/lib/rtl
ExecStart=/usr/bin/node /home/admin/src/RTL/rtl
User=admin
Group=admin
Type=simple
PIDFile=/run/rtl/rtl.pid
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

```bash
~$ sudo cp rtl.service /etc/systemd/system
~$ sudo systemctl enable --now rtl
```

##### Angalia

Angalia huduma:

```bash
~$ sudo journalctl -xe --unit rtl --follow
...
Jul 27 18:27:52 ubuntu node[988638]: Server is up and running, please open the UI at http://localhost:3000
```

Ikiwa haianzi kwa usahihi, simamisha huduma na endesha programu moja kwa moja kupata ujumbe wowote wa hitilafu.

```bash
~$ sudo systemctl stop rtl
~$ export RTL_CONFIG_PATH=/var/lib/rtl; pushd ~/src/RTL; node rtl; popd;
Server is up and running, please open the UI at http://localhost:3000
```

Kutoka kwenye ukurasa wa wavuti wa `BTCPay Server`, kiolesura cha `RTL` kinapaswa kufikiwa kutoka `Mipangilio ya Seva->Huduma` chini ya kichwa cha "Crypto services exposed by your server".

##### Sasisha

Kusasisha kunaweza kuharibu mambo. Kuwa mwangalifu kwenye mfumo hai.

```bash
~$ sudo systemctl stop rtl
~$ cd ~; pushd ~/src/RTL; git pull; npm install; popd;
~$ sudo systemctl start rtl
```
